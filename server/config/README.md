# 服务端配置职责与默认值

这里保存静态目录和服务端硬边界，不读取数据库、环境变量或请求，不持有运行期状态。配置文件中的值是否允许管理员调整，由对应字段的用途决定，不能将整个 config 目录理解为管理端设置。

| 分类 | 来源 | 生效方式 |
| --- | --- | --- |
| 部署参数 | `nuxt.config.ts` 的 runtimeConfig 和部署环境变量 | 数据库地址、可信 Origin、代理名单等部署配置。 |
| 系统参数默认值 | `admin_parameters.parameter_default_value` | 初始化写入，运行时从数据库读取。 |
| 系统参数定义及硬边界 | `parameters.ts`、对应 shared schema/config | 字段说明、校验范围、生效时机及权限；管理员不能修改代码硬边界。 |
| 任务初始化值 | SQL 基线及离线任务种子 | 供显式初始化／测试数据重建使用，不覆盖已有任务。 |
| 任务硬边界 | `tasks.ts` 的 minimumMinutes | 最低执行间隔，管理员不能突破。 |
| 固定业务目录 | permissions、menus、dictionaries、dashboard | 定义权限、页面、业务字典字段及统计指标授权关系。 |

## 系统参数的优先级

1. 有效数据库覆盖值优先。
2. NULL 表示采用数据库默认值；“恢复默认”保存 NULL。缺失记录或无效的数据库默认值会阻止相关策略执行。
3. JSON、类型、范围校验失败时使用数据库默认值并记录安全诊断；密码长度或会话时限关联不合法时，整个关联组读取数据库默认值，避免组合出非法策略。
4. 数据库连接或查询失败仍抛错，不能伪装成默认配置已成功读取。

分页还允许显式请求值：合法的请求 pageSize 优先于数据库有效偏好，只有未指定时才采用偏好。共享的 20 条基础默认值位于 `shared/config/admin/pagination.ts`，供前端首次加载与共享请求解析。

初始化值随当前基线写入数据库；参数定义中的 effect 描述实际生效时机。

| 策略 | 基线初始值 | 生效范围 |
| --- | --- | --- |
| 默认每页条数 | 20 | 未显式指定 pageSize 的列表请求；前端偏好未加载时亦用此值。 |
| 日志单次导出上限 | 5000 | 下一次导出；50000 是独立资源硬上限，来自共享 LOG_EXPORT_HARD_LIMIT。 |
| 登录前会话 | 600 秒 | 新建登录前会话。 |
| 登录会话空闲时限 | 1800 秒 | 新会话；已有会话保留创建时的策略快照。 |
| 登录会话最长有效期 | 43200 秒 | 新会话；Cookie 使用该会话实际 expiresAt，不再另设 12 小时兜底。 |
| 密码长度 | 6–128 个 Unicode 字符 | 下次创建、重置或修改密码；边界与前端长度默认合同共用。 |
| 已知弱口令检查 | 开启 | 下次设置密码；覆盖值必须是真正布尔值。 |

限流次数及窗口可通过登记参数覆盖，运行期读取数据库有效策略：

| 作用域 | 默认次数 / 窗口 | 用途 |
| --- | --- | --- |
| bootstrap | 30 / 600 秒 | 登录会话初始化。 |
| login-ip | 20 / 600 秒 | 按来源 IP 限制登录尝试。 |
| login-account | 5 / 900 秒 | 按账号限制登录尝试。 |
| change-password | 5 / 900 秒 | 本人修改密码尝试。 |
| session-status | 120 / 60 秒 | 会话状态查询。 |
| admin-api | 120 / 60 秒 | 已登录后台请求，不含媒体文件读取。 |
| media-read | 600 / 60 秒 | 后台图片、视频文件读取（含分段请求），按用户独立计数；上传、编辑、删除仍计入 admin-api。 |
| public-inquiry | 8 / 600 秒 | 官网客户咨询提交。 |
| csrf-log | 10 / 60 秒 | 限制安全校验拒绝事件的记录频率。 |
| rbac-log | 10 / 60 秒 | 限制权限拒绝事件的记录频率。 |

缺少任一限流参数时，相关请求会报告配置错误。

## 任务默认值不是运行期兜底

| 任务 | 默认启用 | 初始化计划（北京时间） | 初始化保留期 |
| --- | --- | --- | --- |
| 日志清理 | 是 | 每天 03:00 | 登录 180 天、审计 730 天、安全 730 天。 |
| 会话与限流残留清理 | 是 | 间隔 15 分钟 | 使用会话到期时间及允许的最长限流窗口。 |
| 执行记录清理 | 是 | 每天 04:00 | 固定 90 天，不是管理端可调整的保留天数。 |

正常调度读取数据库的 enabled、schedule 和 retention，执行记录保存当次配置快照。缺失或非法配置不会回退默认计划执行；停止的任务也不会因为代码默认启用而恢复。测试重置辅助位于 `tests/database/reset-data.ts`，仅供专用数据库自动化测试使用。历史迁移包含当时的初始化快照，不随 config 自动改变，也不通过修改历史迁移更新当前设置。

本次收拢不改变已有默认数值，不修改开发库参数或任务记录。以后增加业务参数时，应同时声明默认值、允许范围、覆盖来源、生效时机及非法值处理方式。

## 固定资源边界

`cleanup.ts` 中单批 1000 条、每类最多 20 批为单次清理预算；调用方可降低，不能提高。执行记录固定保留 90 天，与管理员可调整的日志保留期区分。菜单最多 500 个节点、8 层（根计第 1 层）位于 `menus.ts`；排序最大值 9999 位于 `shared/config/admin/menus.ts`，由前后端校验和服务共用。这些值本轮未改变，也不提供数据库覆盖。

## 任务执行参数

`task-execution.ts` 保存固定执行参数：租约 90 秒、轮询 5 秒、正常退出等待 15 秒、调度错误诊断最多每 60 秒一次、无 nextRunAt 时的启动补排最多延后 60 秒。失败／失联最多重试两次，分别延迟 60 秒和 300 秒；成功但达到清理预算时最多续批两次，每次延迟 60 秒。耗尽后恢复正常计划，停止和强制终止不触发重试。它们不接受管理员数据库覆盖；管理员可调整的任务计划、启停及日志保留期仍以数据库配置为准。

`tasks.ts` 只保存任务目录、最低执行频率、已结束状态及结果原因说明；Cron 计算和结束后调度规则位于 policies。`permissions.ts` 与 `menus.ts` 中的路径算法也已归入 policies，配置本身不引用这些策略。

清理审计上下文与执行策略共同引用清理批次预算及共享保留天数边界，避免配置调整后审计校验仍采用旧限制。调度器在线判定窗口为 `TASK_SCHEDULER_OFFLINE_MS`（90 秒），单次执行租约为 `LEASE_MS`（90 秒）；两者含义不同，独立维护，均不接受数据库覆盖。

## Studwell 内部命名

后台 Cookie 名称直接保留在 server/http/auth.ts，各站保持原名称，不再单独提取部署标识。框架 CSRF 标记统一为 studwell-csrf，不附加版本号；任务子进程统一使用 STUDWELL_TASK_* 协议变量，换站不必修改内部协议名称。

升级时同时更新 Web 和任务 worker 产物；已打开后台页面刷新后重新获取 CSRF 令牌。原站品牌资料及数据库结构不随内部命名调整。
