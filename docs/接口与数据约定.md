# 接口与数据约定

本文记录跨模块合同，不手工维护一份容易失效的完整端点副本。实际路由、输入 Schema 和业务响应以 `server/api`、`shared/schemas`、`shared/types` 为入口。

## HTTP 协议

JSON API 使用真实 HTTP 状态，成功形如：

```json
{"success":true,"data":{"items":[],"total":0,"page":1,"pageSize":20},"requestId":"服务器生成的 UUID"}
```

失败形如：

```json
{"success":false,"error":{"code":"INVALID_INPUT","message":"请求参数不正确","fields":[{"path":"name","message":"字段值不符合要求"}]},"requestId":"服务器生成的 UUID"}
```

| 状态 | 常见错误 |
| --- | --- |
| 400 | 输入或 JSON 不合法 |
| 401 | 未认证或会话失效 |
| 403 | 权限、Origin 或 CSRF 拒绝 |
| 404 | 资源不存在或公开目标不可访问 |
| 409 | 版本冲突或业务状态冲突 |
| 413／415 | 请求过大或媒体类型不支持 |
| 429 | 限流，按 Retry-After 处理 |
| 500 | 未知内部异常，客户端不接收底层详情 |

响应包装不适用于所有资源：上传、视频 Range、CSV 下载、搜索文件及图片处理有专门合同。异步任务受理返回 202，不代表任务已经成功。

请求编号由服务器生成，经响应头和响应体返回，不能相信客户端同名头。未知异常只向用户提供安全提示，平台诊断使用有界脱敏信息，不输出连接串、SQL 参数、密码、Token 或完整用户对象。

## 输入、列表与时间

输入采用严格 Schema，拒绝未知字段及重复查询参数数组；不把任意客户端排序字段拼成 SQL。模块自行登记允许的筛选，列表排序由持久层固定。

标准分页接受正整数页码及 10／20／50 条，默认条数可由系统参数决定；检查安全整数和偏移溢出。列表返回实际筛选的总数，越界页可为空，不伪造 total。模块特殊合同按其 Schema 执行。

数据库和 API 使用 UTC／ISO 时间，后台显示和自然日筛选按 Asia/Shanghai。日期范围转换为左闭右开的 UTC 区间，不能截断 ISO 字符串模拟北京时间。

## 认证和会话

| 认证入口 | 用途 |
| --- | --- |
| `GET /api/admin/auth/session` | 读取身份及 CSRF，必要时建立匿名引导会话 |
| `POST /api/admin/auth/login` | 登录并轮换会话 |
| `POST /api/admin/auth/password` | 本人改密，成功撤销会话后重新登录 |
| `POST /api/admin/auth/logout` | 注销当前会话 |
| `GET/PUT /api/admin/auth/profile` | 当前账号本人资料 |

写请求包括登录均要求可信 Origin、会话 Cookie 和 CSRF。Cookie 是 host-only、HttpOnly、SameSite=Lax；HTTPS 使用 Secure。令牌随机生成，数据库保存摘要；认证状态不放 localStorage。

首次改密由服务端限制。每次请求读取账号当前状态和授权；Root 也不能绕过会话、CSRF、限流或未登记接口。查询身份和自动轮询不延长绝对到期时间。

可信 Origin 来自私有配置，不从 Host 或转发头推导。默认使用直接连接 IP，只对精确登记的直连代理接收单个合法 X-Real-IP，代理必须覆盖客户端原值。会话及限流策略见 `server/config/parameters.ts` 与 `server/config/rate-scopes.ts`。

## 权限

`server/config/permissions.ts` 定义代码可用的能力和路由策略，数据库保存角色授权与菜单配置。未知、未登记或停用的能力默认拒绝。普通账号取得启用角色的有效权限并集；菜单范围和页面对象授权仍需另外检查。

菜单隐藏不撤权。角色授权、账号分配和菜单变更还要检查操作者的授权上限，不能通过清空旧授权绕过限制。Root 是账号身份，站点语言及路由／SEO 等 Root 专属流程不会因给普通角色勾选权限而开放。

权限目录同步只增量更新登记及缺失项，不重置 Root、覆盖普通角色或自动赋予新权限。废弃权限码不能复用为更大能力。

## 实体编号和版本

数据库实体使用 BIGINT UNSIGNED，服务端 bigint，对外为十进制字符串；前端不能先转 Number。编号由 `server/db/entity-ids.ts`、`allocate-entity-id.ts` 及持久计数器分配，不使用 MAX(id)+1。

实体编号采用北京时间日期、固定实体类型及当日流水。编号中的日期不是业务发生时间；流水可跳号，不代表记录总数，也不能跨类型比较先后。仍有实体时不得单独重置编号计数器。UUID、会话随机值、业务 code、slug 和 DOM 锚点保持各自语义。

实体写入版本为数值整数，范围以 `entityVersionSchema` 为准，当前为 1–4294967294。更新同时检查版本相等及递增上限，冲突返回 409，耗尽不能回绕。页面内容、结构、设置和发布状态有各自版本，不拿一个旧版本覆盖所有并发状态。

## 事务、审计和媒体

Service 显式组织事务，各 Repository 共用同一执行器。成功审计与写入同事务；审计失败回滚业务。日志仅保存登记的变更白名单，DTO 显式投影，不能直接返回 ORM 全字段记录。

媒体文件与数据库不能假定共享同一事务。删除先移出公开目录暂存，提交成功后清理，失败根据真实状态恢复；启动恢复决定继续清理或还原。外部邮件和独立 Worker 同样通过各自状态协调，不以一次 HTTP 成功代替最终执行完成。

## 公开读取

官网入口位于 `server/api/public`，包括站点设置、站点语言、页面、路由解析、新闻、招聘和咨询等。公开内容只读取发布状态，停用模块及语言按公开合同裁决，不退回草稿或跨语言正文。

`/uploads/`、`/_ipx/` 和 `/search/` 是文件／图片入口，不是旧 mock 内容接口。缓存策略按响应类型明确设置；后台页面、认证和管理 API 不允许共享缓存。
