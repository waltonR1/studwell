# 部署与运维

正式运行依赖常驻 Node、MySQL、持久文件目录和独立任务 Worker。`generate` 是辅助静态输出命令，不是包含后台、业务 API、上传和调度器的正式部署方案。

## 环境配置

| 配置 | 含义 |
| --- | --- |
| `NUXT_DATABASE_URL` | 运行数据库连接，仅服务端可见 |
| `DATABASE_MIGRATION_URL` | 可选迁移账号，仅数据库 CLI 使用，目标必须与运行连接一致 |
| `NUXT_ADMIN_ORIGIN` | 后台可信 Origin，精确匹配协议、域名、端口，无末尾斜线 |
| `NUXT_ADMIN_COOKIE_SECURE` | HTTPS 设 true，本地 HTTP 可设 false |
| `NUXT_ADMIN_TRUSTED_PROXY_IPS` | 可选直连代理的精确 IP，默认不信任转发头 |
| `NUXT_MEDIA_STORAGE_PATH` | 媒体根目录，内部包含 uploads；生产使用独立持久目录 |
| `NUXT_SEARCH_STORAGE_PATH` | 搜索目录，生产与发布目录分离，Web 和 Worker 共用 |
| `NUXT_INQUIRY_SMTP_URL` | 可选咨询邮件服务连接，空值不启用外部投递 |

私有值通过部署平台注入，不写进文档、源码或前端 runtimeConfig。生产 `.output` 不自动加载仓库 `.env`；`npm start` 也不负责替部署平台加载这些值。

Node 要满足 `package.json` 与 `runtime:check` 的约束；当前为 24.x 且至少 24.22.1，内置 Undici 另由脚本校验。MySQL 使用 8.4 和 utf8mb4。应用、迁移、备份和恢复账号按职责授权。

## 构建、发布与升级

```sh
npm ci
npm run runtime:check
npm run build
```

在目标操作系统和架构构建。Sharp 含原生依赖，Windows 产物不能直接作为 Linux 产物。完整产物包括 `.output/server/index.mjs`、`task-worker.mjs`、依赖目录和静态 public；上传目录另外挂载或迁移。

正式启动使用进程管理器执行 `npm start`，或在只部署产物时先独立检查运行环境，再执行 `node .output/server/index.mjs`。进程管理器应管理整棵进程树和退出宽限，不能只杀主进程而遗留 Worker。

升级前先备份并按[数据库](数据库.md)执行迁移。停旧调度器及 Worker，再切换完整产物，检查新进程心跳和业务。回退应用前确认数据库兼容性，不能把切代码当作数据回退。

代理将页面、`/api/`、`/uploads/`、`/_ipx/` 和 `/search/` 正确转发给应用。后台页面与管理 API 不走共享缓存；保留 no-store、Cookie、CSRF 和相关响应头。可信代理要覆盖 X-Real-IP，不能透传客户端伪造值。

## 媒体与图片处理

媒体根目录下的 `uploads` 是运行数据，不进入 Git，也不复制到构建 public。默认根目录按运行方式解析，生产应显式指定稳定的绝对路径，例如 `/srv/studwell/media`。

- 原文件 `/uploads/...` 通过媒体接口读取持久目录，视频支持 Range。
- 图片处理 `/_ipx/.../uploads/...` 使用同一媒体目录；新上传不需要重新构建。
- 静态图片处理读取部署产物的 public，保留后台 Logo 和模板预览媒体等静态素材。

接线在 `nuxt.config.ts`、`server/runtime/images.ts` 和 `server/runtime/media.ts`。维护时保留唯一图片入口，不同时注册默认 IPX 和另一条抢占路由。删除媒体后，原文件与缩放地址都不应继续从旧构建副本提供。

媒体删除暂存位于根目录同级 `.data/media-trash` 下的对应隔离目录。数据库、uploads 和暂存目录一起备份及迁移。启动恢复失败应调查，不通过删除清单强行启动。

删除恢复按单服务实例协调；多个独立实例共享同一媒体目录需要额外并发协调，不能直接据本地单实例验收声称可安全多实例运行。

## 搜索

索引从已发布内容生成，区分普通页面和新闻文章。浏览器按语言加载版本文件并本地匹配，草稿不参与。岗位和咨询不作为独立结果。

`dev` 前置生成一次索引；`build` 不生成索引。生产首次可离线执行 `npm run search:index`，运行中优先从任务管理手动执行搜索重建，避免与调度器并行写目录。

页面、新闻及相关配置发布、恢复或下线会请求重建；任务需启用且 Worker 正常。连续变更会合并，执行中再次变更保留下一次计划。周期兜底不表示每次发布必须等待完整周期。

全部语言文件写好后才切换 manifest。`/search/manifest.json` 不缓存，带版本索引可长期缓存。配置／语言与清单不一致时暂时返回 503，重建后恢复，不提供不匹配的旧索引。

生成器清理超过一天且未被当前清单引用的旧版本。当前版本与近期文件保留。索引可从数据库重建，不能把它当成业务数据备份。

## 调度器与诊断

生产主进程协调任务，每次执行在独立 Worker 中完成，开发／测试模式不启动生产调度。部署必须包含构建生成的 Worker 和依赖，并为数据库连接及子进程预留资源；上限以连接与任务执行配置为准。

手动执行的 202 只表示受理；查看执行记录确认最终状态。暂停周期不停止当前执行；停止在安全边界生效，强杀针对对应执行子进程。重试、租约和已提交批次以任务规则为准，不用外部循环反复提交。

从请求编号、执行编号和诊断编号关联 `admin_maintenance`／`admin_diagnostic`。平台收集受控诊断并配置告警，任务记录不代替告警。监控周期、积压和失败重试按实际任务配置设定，不照搬旧批次的固定阈值。

## 备份和恢复

完整备份包括数据库及迁移凭据、上传文件、媒体暂存和受控环境配置。账号授权另行管理；保护密码摘要、咨询和日志等敏感内容。恢复时使用数据库与文件的完整备份。

备份策略由部署环境确定：频率、保留期限、加密、异地副本、负责人和恢复目标需明确。验证备份退出码、大小及校验值，失败不能覆盖上一份可用副本。

先在独立隔离数据库和文件目录恢复，核对源目标身份、SQL 中的跨库语句及 DEFINER。恢复后检查结构、迁移记录、抽样计数、媒体引用、登录权限、发布和任务，记录耗时及差异，再安排正式切换。未实测的 RPO／RTO 不写成已经达成。

## 上线检查

本机构建和业务验收不替代目标环境验证。上线时检查真实域名与 HTTPS、代理／Cookie、受限账号、媒体上传缩放删除、发布恢复、搜索任务、SMTP（若启用）及备份恢复。当前代码交付范围见[测试与交付](测试与交付.md)。
