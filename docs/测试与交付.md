# 测试与交付

本文说明当前验证方法与交付范围。开发过程和修复历史通过 Git 追溯；验收结果集中维护在本文末尾。

## 验证入口

| 命令 | 范围 |
| --- | --- |
| `npm run runtime:check` | Node 及内置 Undici 运行条件 |
| `npm run lint` | 代码规则和依赖边界 |
| `npm run typecheck` | Nuxt、Vue、TypeScript 及离线数据库工具 |
| `npm test` | 单元及非真实数据库集成测试 |
| `npm run test:db` | 独立 MySQL 测试库上的业务、权限、事务及发布检查 |
| `npm run test:production` | 构建真实产物，在隔离库检查静态图片、运行后上传和删除 |
| `npm run i18n:check` | 固定 UI 翻译键与引用 |
| `npm run build` | 生产构建及独立任务 Worker |

按改动选择验证范围。结构和初始化改动需要新库、重复执行及基线检查；权限、事务和文件生命周期改动需要对应数据库或生产模式检查。构建成功不能替代业务验收。

## 数据库与文件隔离

按 [tests/database/.env.example](../tests/database/.env.example) 配置根目录 .env.test，显式提供 TEST_DATABASE_URL 和 TEST_DATABASE_NAME。仅允许 studwell_test 及受支持的后缀名称，URL 与声明库名必须一致，不能与运行库或迁移库同名。

测试会建立、填充、重建和清理夹具，只能使用允许丢弃的专用库。同一测试库不能被多个重建进程同时使用。test:production 与 test:db 共用测试连接，必须顺序执行。真实外部邮件由目标环境单独验证。

~~~sh
npm run test:db
npm run test:db -- tests/database/site-seed.test.ts
~~~

运行库只读检查使用 db:check、db:init -- `--dry-run` 和 db:site -- `--dry-run`。不得将测试连接用于真实运行数据。

## 夹具与初始化验证

通用模板及系统夹具位于 tests/fixtures/reference，测试图片和视频位于 tests/fixtures/media。测试夹具独立于本站 JSON；网站品牌、页面内容和固定预览样例保留各站差异。

初始化专项验证以下边界：

- db:init 完成表结构、system 与 Root，不填本站配置或展示字典。
- db:site 安装本站配置、模板、页面菜单及业务内容，分别保留草稿和发布状态。
- db:samples 按需补充展示字典、角色、账号与咨询记录；没有可用分类时跳过咨询样例。
- 重复执行保留已有配置、Root 密码、页面内容和管理员编辑的固定样例，仅补缺失项。
- 新库使用 0000_initial 基线；迁移凭据、表结构、外键、JSON、媒体引用及发布投影保持一致。

固定模板预览使用 `template-samples.json` 的样例内部引用，不能断言样例资源 ID 等于新库分配的实体 ID。组件路径检查需要实际构建或 Vite 模块解析，类型检查不能证明 glob 已匹配组件。

## 生产与业务验收

使用真正的 .output/`server/index.mjs` 和任务 Worker，检查：

- 启用语言的发布路由、根入口、404、SEO 和必要素材。
- 登录、首次改密、注销、CSRF／Origin 和普通角色权限隔离。
- 草稿与线上隔离、版本冲突、发布和历史恢复。
- 媒体上传、原文件、缩放、视频 Range、删除和构建后新增文件。
- 新闻、招聘、咨询、咨询幂等及处理流程。
- 调度器、独立 Worker、搜索清单和各语言索引。

指南更新还需核对数据库中实际发布内容、导航、五语言路由和搜索索引。只有场景演示页启用整屏切换；指南与示例表单使用真实内容和业务流程。

界面验收需记录浏览器、页面和视口范围，桌面首页检查不能代表全部页面或手机端。部署目标另行验证操作系统、域名、HTTPS、反向代理、SMTP、容量和备份恢复；本地测试通过不代表生产上线完成。
