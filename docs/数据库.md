# 数据库

Schema 位于 `server/db/schema.ts`。Drizzle 用于 ORM、迁移生成和迁移执行；数据库命令统一由 `scripts/database.mjs` 编排。

## 文件与数据层级

| 层级 | 数据文件（`scripts/database/seed/data`） | 执行脚本 | 内容 |
| --- | --- | --- | --- |
| system | `system.json` | `seed/system.ts` | 参数、任务默认值和安全的基础问询设置；脚本同时创建 Root、权限、基础菜单与基础语言状态 |
| site | `site.json` | `seed/site.ts` | 页面与区块内容、公共配置、语言、路由、SEO、新闻、岗位、本站咨询分类与媒体引用 |
| site | `templates.json`、`template-samples.json` | `seed/site.ts` | 模板字段、编辑布局、渲染器关联及独立固定预览样例 |
| site | `renderers.json`、`module-policy.json`、`image-rules.json` | `seed/site.ts` | 组件登记、模块开关与依赖、图片规则 |
| sample | `samples.json` | `seed/samples.ts` | 可选展示字典、角色、账号和咨询记录 |

纯数据使用 JSON；对应 TypeScript 脚本负责校验、派生值和写入。`scripts/database/baseline.ts` 负责只读基线核验。`scripts/tsconfig.json` 同时供编辑器和命令行检查离线 TypeScript 工具。

系统阶段不需要本站 JSON。本站阶段生成页面维护菜单，并配置实际语言和业务分类。展示字典不影响登录或授权；咨询分类可以为空，未配置可用分类时公开表单不接受提交，样例初始化跳过咨询记录。

## 连接与确认

先准备 MySQL 8.4 数据库及账号，字符集使用 utf8mb4，排序规则使用 utf8mb4_0900_ai_ci。工具不创建 MySQL 数据库或账号。

命令读取项目 .env，进程环境变量优先。NUXT_DATABASE_URL 是运行连接；DATABASE_MIGRATION_URL 可提供独立迁移账号，但主机、端口和库名必须与运行连接相同。配置说明见[环境变量样例](../.env.example)。

写入命令要求交互终端，连接后核对实际数据库名，并输入同名确认。密码交互输入且不回显。日常管理命令拒绝测试库。

## 命令

| 命令 | 效果 |
| --- | --- |
| `npm run db -- --help` | 查看帮助 |
| `npm run db:init` | 执行未应用迁移，补齐 system 与 Root |
| `npm run db:site` | 校验并安装本站配置、模板、页面和业务内容 |
| `npm run db:samples` | 按需补充展示字典、角色、账号和咨询记录 |
| `npm run db:migrate` | 只执行未应用迁移，不填种子 |
| `npm run db:generate` | 根据 Schema 和迁移快照生成 SQL，不执行 SQL |
| `npm run db:check` | 只读检查迁移凭据、表结构、数据引用和发布投影 |
| `npm run db:sync:rbac` | 同步权限目录并补齐默认后台菜单，不自动给普通角色新增授权 |

init、site、samples、migrate、sync:rbac 支持追加 `--dry-run`，预览时不写数据库或文件，不询问密码。check 和 generate 不接受该参数。db:site 可用 `--media-root DIR` 指定媒体存储目录，默认读取 `NUXT_MEDIA_STORAGE_PATH` 或项目 public。

## 首次安装

~~~sh
npm run db:init -- --dry-run
npm run db:init
npm run db:site -- --dry-run
npm run db:site
npm run db:check
# 以下命令可选
npm run db:samples
~~~

数据库表结构和 system、Root 就绪后才能执行 db:site；它不会自动补跑系统初始化。db:init 结束后不询问是否安装本站或样例。新 Root 首次登录必须改密。

完整站点基线在 db:site 结束时检查，也可单独执行 db:check。只完成 system 时，站点策略和图片规则等尚未安装，完整站点基线会报告缺项。

重复执行补缺并保留现有值。权限同步会更新代码目录中的名称和可用状态；已有角色授权和菜单布局由管理员维护。db:site 保留已有页面、工作草稿及发布状态，部分站点内容冲突时停止；它不是修改 JSON 后覆盖运行内容的更新工具。模板样例只补空值，后台已有样例保留。已有示例账号不重置密码、恢复删除状态或重新分配角色。

迁移、系统数据和本站内容分阶段完成，后续阶段失败不会撤销前面已完成的阶段。DDL 的回退不能依赖应用事务。

## 本站内容与媒体

`site.json` 分别声明草稿和发布内容，未发布页面及编辑保持未发布。资源引用使用语义键，新库安装时分配实际编号。初始化素材路径相对于 public，读取前验证 SHA-256；运行上传目录随数据库备份。

本站安装通过事务完成资源身份、媒体、业务记录、区块、路由及最终发布配置的写入，随后恢复工作草稿。初装建立当前内容，不复制旧账号、咨询记录、审计日志或全部发布历史。

`template-samples.json` 保存独立固定预览，使用样例内部引用和 public 素材，并覆盖本站模板。它不从当前发布页面生成，不随日常页面编辑自动刷新。

## 迁移基线与升级

当前迁移起点为 `drizzle/0000_initial.sql`、`meta/0000_snapshot.json` 和 `meta/_journal.json`。0000 只建立当前表结构；系统、本站和展示数据分别由种子脚本填入。初始库不执行历史业务数据的清理 SQL。

后续结构变更使用 db:generate 生成新的增量迁移，审阅后提交 SQL、快照及 journal。已部署的迁移凭据须与当前代码一致；未知哈希或迁移缺口会停止执行，不能靠删除凭据或重跑初始 SQL 绕过。

已有库升级先备份数据库和素材，再执行 db:check、db:migrate，权限目录变化时执行 db:sync:rbac，最后复查基线及相关业务。Git 回退不恢复数据库。

## 备份与测试

整站恢复使用数据库、上传文件和受控环境配置的完整备份。恢复流程见[部署与运维](部署与运维.md)。

npm run test:db 只操作显式配置的专用测试库，会建立、重建和清理夹具，不能指向运行库。配置与隔离要求见[测试与交付](测试与交付.md)。
